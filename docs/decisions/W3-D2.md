# W3-D2 decisions (remaining UI screens, real-backend readiness)

Format as in `docs/DECISIONS.md`. IDs are local (`D2-01`...).

## D2-01 Table, preview and search reuse one component through "slots"
`ctl-step.js` builds the table operations over a slot (where the step state lives). The step review uses `state.step`; Custom search results use `state.custom.step` (actions prefixed `custom_`). `views/step/table.js` takes a step state and operations, so both show the same table.

## D2-02 Errors: toast, inline or disabled
Every rejected command becomes a toast (`ctx.fail`, `guard`). Loads of a whole view (History, disk tree, breakdown, categories) show an inline error block with Retry. `not_implemented` and `unsupported` mark the feature in `state.unavail` and its controls render disabled with the hint as title (`ctx.feature`). Stale answers are dropped with request generations (`lib/gens.js`).

## D2-03 History: confirm before undoing a run; refusals come back through the job
`restore_entries` and `undo_run` report an occupied original place per item in `JobOutcome.errors` (code `conflict`); there is no pre-check command. So "Undo run" always asks first, lists refusals already known from loaded entries (`state: undo_failed` with `error`), and after the job a result panel lists every refusal with its reason. Entries refused earlier stay restorable.

## D2-04 Export destination
`report_export` and `results_export` need `dest`. The in-app browser gets an `export` mode with a file name field (default `myjanitor-report-<run>.csv` and so on); the path is joined in JS only for that new name (`joinPath`, separator from `app_info.platform`). Names with separators are refused.

## D2-05 Step "Filter these results" is the path filter of `candidates_page`
The IPC filter is a case-insensitive path substring, so the step filter is a text box, not the quick query. The full query and rule builder live in Custom search.

## D2-06 Size breakdown (OPT-ENG-09) and compare (OPT-ENG-10) degrade
IPC has no per-file size parts and no "after" sample. The preview pane draws parts from `Candidate.columns["part:<name>"]` (bytes) when present, else a now-versus-after bar. Compare is enabled only when the preview is a waveform (the after side is the same waveform with the silences cut); otherwise disabled with the reason.

## D2-07 Platform awareness
`lib/platform.js` turns `app_info`, `drives_list` features and `tools_list` into a short label (Windows only, Needs a Btrfs volume, Requires ffmpeg on PATH). The backend reason always wins on a disabled card; the label is an extra chip.

## D2-08 Mock additions
Scenario `rich` (`?scenario=rich`): ffmpeg missing (video and audio disabled), a Btrfs card, three runs of history with journal entries (failed, skipped, refused), faults on an apply step, archive settings. Options: `?platform=linux`, `?ni=cmd1,cmd2` (not_implemented), and test helpers `failNext`, `disable`, `listenerCount`. The mock now returns `search_parse` without `rule` when there are errors, as the engine does, and uses `seven_zip` for the archive format (the real enum name).
