# W3-D1 decisions: contract revision, engine facade, Tauri commands

Format of `docs/DECISIONS.md`; ids D-3D1xx. Rule applied throughout: user data
safety first.

## Part 1: contract revision (additive)

### D-3D101 No new field on structs other crates build literally
- **Context:** `DetectContext` and `Candidate` are built with struct literals in
  merged crates and in the optimisers being written in parallel; a new field would
  break every one of them.
- **Choice:** environment facts travel in `DetectContext::params` under reserved keys
  (`mj_core::detector::env::{SYNC_ROOTS, DOWNLOADS, FONT_FOLDERS, PROTECTED}`,
  NUL-separated lossless paths) read through the new methods `env_paths` /
  `is_protected`; per-candidate pixels and safety class are reserved `columns` keys
  (`resolution`/`pixels`, `safety`) read through `Candidate::pixels()` /
  `safety_override()`. A missing env key means *unknown*, never "none".
- **Why:** zero breakage for parallel workstreams; W2-B already fills
  `columns["resolution"]`, so `highest_resolution` re-application works at once.

### D-3D102 Struct fields that were added
`ActionItem::expected_id`, `JournalEntry::{original_mode, previous_compression,
undo_of}`, `SavingsSummary::reclaimed`, `FsListDirResponse::omitted`: all
`#[serde(default)]` (old JSON and old journals load unchanged). Only `mj-actions` and
the engine build `ActionItem` / `JournalEntry` literally; both were adapted.

### D-3D103 `Condition::Media { cond }`
- Struct variant (not newtype) because `MediaCondition::Number` has its own `field`
  key, which would collide with `Condition`'s `field` tag.
- The types moved to `mj-core`; `mj-filters` re-exports them under the old names.
  The evaluator gets a `Leaf::Media` (cost 150, after header reads, before content)
  and asks `ContentConfig::media`; without a provider, or without metadata for a file,
  the leaf is *unknown* (three-valued: never selected, also not under NOT) and counted
  as `media_without_metadata`.

### D-3D104 Error codes
`Error::NeedsElevation` (`needs_elevation`) and `Error::Confidential`
(`confidential`). `mj-actions` now skips signed/labelled/encrypted items with
`confidential` (was `protected`) and maps a permission-denied failure on a path
`safety::needs_elevation` recognises to `needs_elevation`.

### D-3D105 Journal fields used by `mj-actions`
`original_mode` is recorded on every new entry (Unix mode bits, Windows read-only
flag) and restored when a hard/reflink replacement is undone (closes the D-2E07 gap);
`previous_compression` is recorded by `fs_decompress`, which becomes undoable (undo
compresses again with that algorithm); undo-run entries carry `undo_of`. The guard
compares `expected_id` with the fresh file id when both are known. The stale module
doc that said the action engine trusts its caller for confirmation was corrected.

## Part 2: engine facade

### D-3D106 Lock order and threading
`results` (RwLock) before `plan` before `jobs`; no lock is held across file I/O or
while emitting. The scan runs on one `mj-scan` thread; analyses fan out with
`parallel_map` (2-8 workers, each `catch_unwind`); jobs that change files run one at a
time on one `mj-jobs` worker in queue order (simplest way to guarantee two jobs never
touch the same files; `parallel_jobs` is not used yet); dry runs only read and run on
their own thread.

### D-3D107 Generations
`scan_start` refuses while a scan thread is alive (also while stopping), so a stale
scan can only be the one being stopped; results, plan refresh, cache prune/save and
`opportunities://changed` happen only when the scan's generation is still current.
`scan://detector` events of a stale generation are not sent.

### D-3D108 Locked rows
Protected rows (`BLOCKING`) and signed / labelled / encrypted rows while the matching
`skip_*` setting is on are not actionable: `selection_set` cannot select them, they are
never expanded into items, and they are counted in the checklist
(`skipped_confidential`) and the dry-run warnings. `mj-actions` would skip them anyway
(code `confidential`); locking says so before the user applies. Labelled rows also get
`Badges::CONFIDENTIAL`. Content inspection runs only on candidate files with document
extensions (bounded reads), never on online-only files.

### D-3D109 Disabled cards
An optimiser whose `availability` is disabled is not analysed; an analysis that
returns `not_implemented`/`unsupported`/an error becomes a disabled card with the
message as reason. Disabled cards are listed (after available ones), never counted in
the summary, and cannot be added to the plan (`unsupported`).

### D-3D110 Sizes
Card, plan, dry-run and reclaimed figures for removals use the scan's reclaimable
sizes (allocated; folders = subtree totals; online-only = 0). The dry run takes the
checks (guard, stamps, existence, confirmation) from `mj_actions::dry_run_with`, the
bytes from the index, and subtracts what other hard links keep. Optimise steps use the
action engine's measured numbers.

### D-3D111 Environment for detectors
The engine fills `mj_core::detector::env` (platform sync roots when detectable,
`~/Downloads`, system and user font folders, built-in + user protected paths and
MyJanitor's own folders) and W2-B's `synced_folders` / `downloads_folders` /
`font_folders` when the user left them empty.

### D-3D112 Apply rules
Root allowlist = the roots of the scanned index; MyJanitor's data, cache, journal,
quarantine and temp folders are always protected. Confirmation is required when the
step's class, the action with the dialog's originals choice, or
`mj_actions::engine::requires_confirmation` says so; only then `confirmed: true`.
Online-only rows are skipped for every action except copy (removing a placeholder
deletes the cloud copy). Hard/reflink items need their group's keeper; none = skipped.
One apply run at a time (`conflict`). Applied (journal `done`) items leave their cards;
the applied step leaves the plan. Run roots and step titles are kept in
`<data>/run-meta.json` so undo has a guard that covers the originals (fallback for
runs without metadata: each original's parent folder) and reports keep their section
titles.

### D-3D113 Undo, restore, purge
Queued jobs (they change files) in their own undo run (`start_undo_run`, `undo_of`).
`restore_entries` refuses entries that are no longer undoable. The quarantine summary
ignores undo records (they copy their source's `retained_at`); fixed in
`mj_actions::quarantine::held`.

### D-3D114 Step parameters
`step_params_set` merges the preset's values then the request's (unknown keys are
`invalid_input`) and re-runs that one detector/optimiser analysis synchronously on the
current index (hashes come from the cache). Lossy = a lossy toggle on, or values equal
to a lossy preset; it switches the plan step to `lossy_opt_in`.

### D-3D115 Previews
Small web images (≤ 4 MiB) are returned as-is in base64 (the webview scales them;
no decoder is added), text files as their first 4 KiB with control characters
removed, folders and binary files as `none`, online-only files are never read.
Waveforms wait for the W3-C audio optimiser.

### D-3D116 Free space
`mj-platform` already has `statvfs` (Linux) and `GetDiskFreeSpaceExW` (Windows) in
`scan/volumes.rs`; `crates/platform/src/disk.rs` was not needed. `drives_list`
attributes each plan step's estimate to the volume of each selected item.

### D-3D117 Tauri shell
One `myjanitor.lock` per data folder: Windows keeps it open without sharing; Linux
checks the pid in `/proc`; a second instance exits with a message (two instances
would interleave journal records). The event bridge re-applies the 50 ms per-source
throttle and never drops a final value or a non-progress event. On `RunEvent::Exit`
the engine stops scans/jobs between items (5 s), saves the scan cache and run metadata.

### D-3D118 Tests never touch real data
Tests build their trees and app folders in `TempDir`s, the allowlist is the tree root,
and `EngineConfig::trash_route = Quarantine` keeps the user's real Trash out of tests.

### Known gaps
- `schedule_run_now` (W3-E) and optimiser cards/estimates (W3-A/B/C) are still
  `not_implemented` from their owners; the engine paths are ready (trait-driven).
- One job at a time; no per-volume parallelism yet.
- Windows liveness of a stale instance lock relies on the OS releasing the handle.
- The synced-folder alternative depends on `dehydrate`, which is Windows-only.
